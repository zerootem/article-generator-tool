# مولّد المقالات

واجهة عربية لإنشاء مقالات HTML وتحرير عناصرها. المشروع في طور إعادة التنظيم من صفحة واحدة إلى ملفات واضحة، مع إبقاء السكربتات القديمة مؤقتاً كي لا تتعطل الوظائف غير المنقولة بعد.

## التشغيل والتأكد

تحتاج Node.js وnpm. نفّذ `npm ci` ثم `npm run dev` للمعاينة المحلية، و`npm test` لتشغيل اختبارات المحرر وWorker، و`npm run build` لفحص TypeScript وبناء ملفات GitHub Pages داخل `dist/`. لا ترفع `dist/` أو `node_modules/` إلى Git؛ GitHub Actions يبني `dist/` ثم ينشره.

## بنية المشروع

`index.html` يحتوي هيكل الصفحة. `src/styles/` يحتوي CSS الخارجي، و`src/main.ts` نقطة دخول TypeScript وجسر مؤقت للملفات القديمة، و`src/editor/ranges.ts` منطق تحديد نطاقات العناصر المحررة واختباراته، و`src/prompts/` قوالب المطالبات. `public/assets/js/legacy/` يحتوي بقية السلوك المنقول من الملف القديم تدريجياً. `worker/` يحتوي خادماً اختيارياً مستقلاً مبنياً على Cloudflare Workers، ومصادره واختباراته وإرشادات إعداد الحساب.

## التوليد ومفاتيح API

تظل خيارات المزود المباشر وPuter متاحة. وضع Worker يظهر فقط إذا حُدد `VITE_WORKER_URL` وقت البناء عبر متغير بيئة محلي أو GitHub Actions، ولا توجد حالياً قيمة لهذا المتغير في المستودع. حتى يتم نشر Worker وضبط Cloudflare Access وKV والسر، سيظل هذا الوضع غير متاح ولن يرسل الأداة طلبات إلى خادم غير مجهز.

في مسار المفاتيح الشخصية، يجب فتح القفل بكلمة مرور رئيسية قبل حفظ بيانات جديدة. تُشتق مفاتيح AES-GCM من كلمة المرور وتبقى مفاتيح التشفير في ذاكرة الصفحة حتى القفل. قيم Base64 القديمة لا تُعامل كتشفير؛ بعد فتح القفل تُرحّل قيم AI القديمة إلى AES-GCM، وتُرحّل قيم Blogger عند حفظ إعداداتها التالية. التشفير المحلي لا يحمي من XSS أو امتداد متصفح خبيث أو جهاز مخترق، ولا يغني عن الخادم إذا كان التطبيق موزعاً على مستخدمين متعددين.

تفاصيل Worker ومتطلبات الحساب وحدود المصادقة موجودة في [`worker/README.md`](worker/README.md)، والمراجع الرسمية في [`worker/REFERENCES.md`](worker/REFERENCES.md). لم يُنشر Worker ضمن هذا التحديث، ولا يحتوي المستودع على أي مفتاح API أو بيانات دخول.

## النشر

يقوم `.github/workflows/pages.yml` ببناء الموقع ونشر `dist/` عند دفع تغيير إلى `main`. يجب أن يكون مصدر Pages مضبوطاً على **GitHub Actions** حتى يعمل هذا workflow؛ `worker/README.md` يصف إعداد Worker بصورة مستقلة. لا تنشر تعديلات على `main` إلا بعد اجتياز الاختبارات والبناء ومراجعة diff.
